4. PRERREQUISITOS (elegir UNO de los dos caminos)
--------------------------------------------------------------------------------
OPCION A - Build en maquina Linux real/VM
  - Linux (Ubuntu 22.04/24.04 recomendado, x86_64)
  - Node 20+, Rust stable
  - Dependencias Tauri Linux:
      sudo apt install libwebkit2gtk-4.1-dev build-essential \
        libssl-dev libayatana-appindicator3-dev librsvg2-dev \
        libgtk-3-dev libsoup-3.0-dev javascriptcoregtk-4.1-dev
  - Este proyecto esta en Windows: hay que copiar el codigo a la maquina Linux
    (o usar OPCION B).

OPCION B - GitHub Actions (recomendada, sin maquina propia)
  - El repo ya esta en github.com/IronLord02/pipper-tts-gui
  - Workflow ubuntu-latest con tauri-action:
      - tauri-apps/tauri-action@v0
      - steps: checkout, setup-node, setup-rust, npm ci, npm run tauri build
  - El .AppImage sale como artifact del workflow.
  - VENTAJA: despues sirve igual para macOS (macos-latest) sin tocar nada.

7. RIESGOS Y GOTCHAS (leer antes de compilar)
--------------------------------------------------------------------------------
- [GOTCHA] Icono: tauri.conf.json tiene solo .ico; AppImage requiere PNG.
           Sin icon.png el build puede fallar o salir sin icono.
- [GOTCHA] El warning ".rsrc merge failure" que ves en Windows es solo del
           linker MinGW; en Linux NO aparece.
- [GOTCHA] Si piper linux necesita una version distinta de onnxruntime a la
           del tarball, hay que bajarla aparte (misma mayor que la del .so).
- [GOTCHA] Tauri AppImage: webkit2gtk NO va dentro del paquete -> en distros
           viejas/minimas hay que instalarlo. Normal para la industria.
- [RIESGO] Si la distro destino tiene webkit2gtk-4.0 (viejo) en vez de 4.1,
           el AppImage no abre. La solucion estandar es apuntar a Ubuntu
           22.04+ para build y doc "requiere webkit2gtk-4.1".
- [RIESGO] El proyecto usa carpetas relativas al exe (current_exe). En
           AppImage el binario corre desde /tmp/... montado, la resolucion
           actual con fallback a %APPDATA%... en Linux el fallback usa
           dirs::data_dir -> ~/.local/share. VERIFICAR que la carpeta output
           y settings caigan donde corresponda en Linux (probar en paso 5).
